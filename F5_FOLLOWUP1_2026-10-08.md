# F5 Follow-up 1 - Explicit Arming and Minimal Human Approval Channel

Date: 2026-10-08
Status: **Phase 13 (Human Escalation) work pulled forward**, the same way the
Phase 11 bridge was labelled. This is deliberately MINIMAL. Workflow state,
confidence thresholds and ambiguity escalation remain out of scope.

## The two open problems this session addressed

1. Under activation no human could approve anything, so every
   out-of-workspace operation was unreachable in production.
2. Arming appeared to depend on `AIEngine.__init__` calling `load_dotenv()`.

## Part A - Explicit arming

### A.1 Entry points, measured in real fresh processes

`.env` present and declaring `GENESIS_WORKSPACE_ROOT`:

| entry point | armed BEFORE |
|---|---|
| bare executor import | **NO** |
| executor + `ActionPlan` constructed | **NO** |
| `AIEngine` constructed | yes - *only* because `__init__` calls `load_dotenv()` |
| adapter imported | **NO** |
| `GenesisOS` runtime | **NO** |
| explicit `load_dotenv()` | yes |

The product itself was running unarmed. A security control whose state
depended on an unrelated object's construction order was not a control you
could reason about.

### A.2 The loader

`genesis_os/genesis_config.py`:

- **Explicit.** `workspace_root()` deliberately does NOT call it. Auto-loading
  would make "variable unset" unreachable, so no test could ever verify the
  unarmed path.
- **Idempotent.** Repeat calls change nothing and report `already_loaded`.
- **Never overrides** an existing environment variable. An operator who
  exports a root for one run is not overruled by the checked-in `.env`.
- **Tolerant.** A missing or unreadable `.env` is not an error; Genesis still
  starts, unarmed.
- **Cwd-independent.** `.env` is located relative to the package, not the
  working directory.

Armed AFTER, from a fresh process: bare executor **still NO** (correct),
`load_genesis_config()` **yes**, `GenesisOS.show_startup()` **yes**.

## Part B - The approval channel

`genesis_os/approval_channel.py`. Deliberately minimal and separate, so a
structural test can police property 1.

| # | property | how it is enforced | test |
|---|---|---|---|
| 1 | Only a human channel approves | `approve` is called from exactly one product module; AST call-site test asserts no other caller | `test_only_the_approval_channel_calls_approve`, `test_approval_channel_is_not_importable_from_a_capability` |
| 2 | Prompt content is derived, never model-written | fixed template over the plan's own fields; `build_request` has no description/text/prompt parameter | `test_prompt_cannot_be_given_model_prose`, `test_non_path_argument_values_are_never_rendered` |
| 3 | Protected paths visibly distinct | different header plus a typed phrase instead of `y` | 6 protected-path tests, `test_y_does_not_approve_a_protected_path`, `test_plain_approve_does_not_approve_a_protected_path` |
| 4 | Non-interactive denies | no TTY / EOF / unselectable stream all deny; no auto-approve flag exists | `test_no_tty_denies`, `test_closed_stdin_denies`, `test_timeout_denies`, `test_no_auto_approve_option_exists_in_the_channel`, `test_no_auto_approve_env_var_is_honoured` |
| 5 | Tool output cannot answer | buffered stdin discarded before the read | `test_injected_text_in_a_tool_result_does_not_approve`, `test_prompt_is_discarded_before_reading` |
| 6 | Single-use and argument-bound | fresh token per approval; grant bound to the argument hash | `test_attack_different_target_after_approval`, `test_attack_transplant_grant_to_another_operation`, `test_attack_pending_unapproved_request`, `test_two_pending_requests_approving_a_does_not_authorise_b`, `test_attack_fabricated_approval_id`, `test_different_filename_case_insensitively_is_refused` |
| 7 | No repeat prompt in a turn | denial recorded against (operation, hash) for the turn | `test_denied_request_is_not_re_prompted_in_the_same_turn`, `test_a_different_turn_may_prompt_again` |
| 8 | Minimal audit record | append-only JSONL; hashes, names and paths only, never values | `test_audit_records_hash_and_paths_but_never_contents`, `test_audit_is_append_only` |

### Two real bugs the adversarial tests found

1. **`_read_line` crashed instead of denying.** A stdin without `fileno()`
   made `select.select` raise `TypeError`, which was not caught, so
   `request_approval` raised rather than returning a denial. Property 4
   requires denial. Now fails closed with a timeout-style denial.
2. **Every string argument was resolved as a path.** A `content` argument of
   `"x"` was displayed as `resolves to: ...\backend\x` - a factually wrong
   line in a security prompt. Resolution is now restricted to path-bearing
   argument *names*.

### One test expectation corrected, not weakened

`Case.txt` and `CASE.TXT` hash **identically** - `_approval_arguments_hash`
normalises case. On Windows these are the same file, so a case variant is a
valid authorisation for the same target, not a bypass. The original test
asserted the opposite. It now documents that, and asserts the property that
actually matters: a genuinely different filename is refused.

### A regression I introduced and caught

My first insertion of `announce_boundary_state` landed *inside* the
`GenesisOS` class body. Because the inserted function was at column 0 and the
following `def show_startup` at column 4, Python parsed it happily - the
class simply absorbed nothing, and every subsequent method became a nested
function of the new module-level one. `GenesisOS` went from 26 members to 3,
and 22 live-marked tests failed with
`AttributeError: 'GenesisOS' object has no attribute 'classify'`.

**The fast suite could not see it**: all 22 are `live`-marked and deselected
by `-m "not live"`. Only the full run caught it. The function now sits at
genuine module level immediately before `class GenesisOS`, and the class is
verified to have all 26 members with `classify`, `run_level3`, `show_startup`
and `run` present.

This is the second time the fast gate's blind spot has cost real time.

## Residual follow-ups

1. **Generated-artifact defaults resolving into the workspace** (top
   priority next). The Phase 0 bridge still writes to `backend\` and is gated;
   approving it is now possible but clunky. Own session and proof.
2. **Two-axis refinement.** Ordinary reads outside the root should be free;
   reads of a named sensitive list stay gated. Blast radius measures
   reversibility, not confidentiality.
3. **Remaining Phase 13 scope.** Workflow state, confidence thresholds,
   ambiguity escalation, a real approval UI, and formalising the audit log
   into something auditable rather than append-only JSONL.
4. **In-process mutability of the root (low severity).** `os.environ` can be
   changed by any in-process code after startup, so the boundary root is not
   immutable at runtime. Only a TTY-only process with no other in-process
   writers would close this.
5. **8.3 short names and symlinks unverified on this host.**
6. **The fast gate is an iteration tool, not a release gate.** It deselects
   `live`-marked tests, and both times it was trusted as a gate it missed
   real breakage (this session's class-truncation regression; last session's
   `load_dotenv` leak). Release decisions need the full run.
7. **`load_dotenv()` still runs inside `AIEngine.__init__`.** Part A removed
   the *dependence* on it, but the side effect remains. Moving config loading
   out of the constructor would close the pollution at source.
8. **The executor's grant check does not consume.** `grant_is_valid_for` is a
   pure validation; single-use is enforced by `ApprovalStore` on the adapter's
   consume-and-mint path. The approval channel mints a fresh token per
   decision, so the guarantee holds by construction - but a caller that reuses
   a grant object against the executor directly would not be stopped.
